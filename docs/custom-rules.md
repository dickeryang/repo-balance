# 自定义规则（Custom Rules）

> 本文档描述自定义规则的 JSON 格式与行为口径，对应路线图中期任务「配置驱动的自定义规则」。
> 规则由内置检查器 `custom-rules` 执行；它是 WASM 沙箱插件机制落地前的轻量替代。

## 一、定位

内置六个检查器覆盖通用健康度；自定义规则让团队把**自己的规约**（禁用 API、遗留标记、内部约定等）
变成可复现的体检结论：一条规则 = 正则 + 路径 glob + 严重度 + 维度 + 话术。

- 正则由 [regex](https://docs.rs/regex) 执行，**线性时间匹配、无回溯**，用户正则不会拖垮扫描；
- 规则只作用于**工作区文件文本**（与敏感信息检查器同一份切片）；
- 命中样本与敏感信息同样**构造时即掩码**，导出与 IPC 不复原。

## 二、JSON 格式

规则文件顶层为**规则数组**；每条规则字段如下：

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `id` | ✅ | — | 稳定唯一标识，仅允许字母、数字与 `.` `_` `-`，≤ 64 字符；进入 finding id（`custom-rules.<id>:<路径>`） |
| `title` | ✅ | — | 结论标题，≤ 200 字符 |
| `pattern` | ✅ | — | 匹配正则（Rust `regex` 语法，可用 `(?s)` / `(?i)` 等内联开关），≤ 1024 字节 |
| `suggestion` | ✅ | — | 可执行的中文改进建议，≤ 200 字符 |
| `severity` | | `warning` | `critical` / `warning` / `info` |
| `category` | | `structure` | `structure` / `history` / `branches` / `deps` / `security` |
| `path_glob` | | 不限 | 路径限定，如 `*.rs`、`src/*.ts`；`*` 任意字符、`?` 单字符；无分隔符的模式按 basename 匹配 |
| `ignore_case` | | `false` | 是否忽略大小写 |

示例：

```json
[
  {
    "id": "no-console-log",
    "title": "前端代码残留 console.log",
    "pattern": "console\\.log\\(",
    "path_glob": "src/*.ts",
    "severity": "warning",
    "category": "structure",
    "suggestion": "删除调试语句或改用统一日志封装后重新提交"
  },
  {
    "id": "forbidden-todo",
    "title": "存在未经跟踪的 TODO 标记",
    "pattern": "TODO(?!:issue-)",
    "severity": "info",
    "category": "history",
    "ignore_case": false,
    "suggestion": "把待办转成 issue 并在注释中回链（如 TODO:issue-123）"
  }
]
```

## 三、使用方式

### 图形界面

连接页「检查器配置」→「自定义规则」分组：

- 「+ 添加规则」逐条编辑，表单即时校验（正则语法、ID 唯一、必填项）；
- 「导入 JSON」读入规则文件（**整体校验，要么全部生效要么明确报错**）；
- 「导出 JSON」把当前规则备份为文件（含非法规则时阻止导出）。

规则随扫描配置保存在本地（`localStorage` 的 `rb-scan-config`）。

### 命令行

```bash
rb scan <path> --rules path/to/rules.json
```

- 指定后启用 `custom-rules` 检查器，并在人类可读输出中标注启用条数；
- 文件不存在 / JSON 非法 / 正则无法编译一律**快速失败**（非零退出码），不做静默降级。

## 四、行为口径

| 口径 | 说明 |
|---|---|
| 命中聚合 | 按「规则 × 文件」聚合为一条结论：证据含命中次数、前 5 处行号与首个匹配的掩码样本 |
| 结论数量上限 | 单条规则最多产出 50 条文件级结论，超出时追加一条 `info` 结论如实说明「共命中 N 个文件，仅列出前 50 个」 |
| 采样预算 | 与敏感信息检查器共用文件内容切片：单文件 1 MiB / 全仓 32 MiB，二进制与超预算文件跳过（不误报） |
| 忽略规则 | `.repobalance-ignore`（含内置默认忽略项）在采集层先生效，被忽略的文件不参与自定义规则匹配 |
| 维度覆盖 | 规则维度去重后计入评分覆盖度；**无规则时不注册该检查器**，避免无规则的维度假满分 |
| 历史范围 | 自定义规则只看工作区当前状态，不参与历史遍历限制（`--max-commits` / `--since-days`） |

## 五、与插件机制的关系

自定义规则是「配置驱动」，能力边界固定（正则 + 路径），换取零风险与零依赖；
长期路线图中的 WASM 沙箱插件机制则在验证真实需求后提供跨语言、可计算的扩展能力
（见 [`roadmap.md`](roadmap.md) 长期任务）。
